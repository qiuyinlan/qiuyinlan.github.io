更新时间：2026-11-14
前置知识：Elasticsearch 基础、向量检索概念
对应项目：AGENT/pilot

一、RAG 是什么？

RAG（Retrieval-Augmented Generation）= 检索增强生成。

用一句话概括：先查资料，再回答问题。

为什么需要 RAG？

  • 大模型有知识截止，不知道训练数据之后的事
  • 大模型会胡说八道（幻觉）
  • 企业有自己的私有知识（文档、日志、代码），模型没见过

RAG 解决的就是：让 AI 基于你的知识库回答问题。

2.1 BM25：关键词检索

作用： 找”字面上相似”的文档。

例子：

  • 你搜：”Kubernetes 部署”
  • BM25 会找标题/内容里有 “Kubernetes”、”部署” 这些词的文档

底层数据结构：倒排索引（Inverted Index）

好处： 搜一个词，瞬间知道哪些文档包含它。

分词时机：

  • 写入时：ES 接收文档 → 分词 → 建倒排索引
  • 查询时：同样的分析器再分一次 → 查倒排索引 → 算 BM25 分数

因为互补。

“prometheus 告警规则” ✅ 专有名词命中 ✅ 语义理解

工程实践： 两路同时跑，然后用融合算法合并结果。

三、RRF 融合：把两路结果合为一份

两路检索各返回一份排序结果，怎么合并？

问题： BM25 分数和向量相似度值域不同，不能直接相加。

  • BM25 分数：可能是 2.3、5.1、0.8…
  • 向量相似度：0 到 1 之间（如 0.85、0.72）

解决方案：RRF（Reciprocal Rank Fusion，倒数排名融合）

3.1 RRF 公式

  • rank = 文档在某路检索中的排名（第 1 名 rank=1，第 2 名 rank=2）
  • k = 常数，工程常用 60
  • Σ = 把所有检索路的结果累加

核心思想： 只依赖排名，不依赖原始分数。

3.2 计算例子

假设 k=60，两路检索结果：

文档 BM25 排名 向量排名 RRF 分数计算 最终分数
文档 A 第 1 名 第 3 名 1/(60+1) + 1/(60+3) 0.0323
文档 B 第 2 名 第 1 名 1/(60+2) + 1/(60+1) 0.0327
文档 C 第 5 名 - 1/(60+5) 0.0154
文档 D - 第 2 名 1/(60+2) 0.0161

说明：

  • 文档 A 在两路都出现，累加两项
  • 文档 C 只在 BM25 出现，只加一项
  • 文档 D 只在向量出现，只加一项
  • 不需要两路齐全才能计算

3.3 为什么 k=60？

来源： 2009 年 SIGIR 论文《Combining results of multiple information retrieval systems using Reciprocal Rank Fusion》

实验结论：

  • k 太小（如 5）：第 1 名碾压后面，排名差异被放大太多
  • k 太大（如 100）：第 1 名和第 50 名差不多，排名差异被平滑太多
  • k=60 在多个数据集上效果最好

直观理解：

特点：

  • ✅ 第 1 名和第 2 名差距最大（鼓励排前面）
  • ✅ 排名越往后，差距越小（尾部不重要）

五、RRF 的优缺点

✅ 优点

  1. 实现简单：几行代码就能搞定
  2. 调参少：只需要调一个 k 值（固定 60 就行）
  3. 不用归一化：BM25 和向量分数单位不同，RRF 只看排名
  4. 鲁棒性强：多路检索都认可的文档会排前面
  5. 支持多路叠加：两路、三路、更多路都可以

❌ 缺点

  1. 丢掉原始分数信息：BM25 第 1 名和第 2 名的分差、向量相似度的差距，全部被平滑成排名
  2. 差的路也有权重：如果某路检索质量很差，它依然会给结果分配权重
  3. 需要每路先召回 topN：一般每路先召回 100 条，再送入 RRF，不会拿全量文档计算

六、工程实践建议

6.1 每路召回数量

不要直接召回 final_top_k，要多召回一些。

原因：

  • 某路检索可能把相关文档排在第 10 名
  • 如果只召回 5 条，相关文档就被漏掉了
  • RRF 融合后再排序，取最靠前的 5 条

6.2 中文分词器

Pilot 默认用 standard，生产环境建议换 ik_max_word。

区别：

  • ik_max_word：尽可能多分词（”中华人民共和国” → “中华/华人/人民/共和/共和国…”)
  • ik_smart：最少切分（”中华人民共和国” → “中华人民共和国”）

6.3 向量维度

Pilot 用 1024 维，这是 Embedding 模型决定的。

常见维度：

  • text-embedding-ada-002：1536 维
  • bge-large-zh：1024 维
  • m3e-base：768 维

注意： 索引创建后维度不能改，要改只能重建索引。

7.2 常见问题排查

问题 可能原因 排查方法
检索结果为空 分词器问题 查 ES 索引 mapping，看 analyzer
向量检索慢 没建向量索引 查 ES 索引是否有 vector 字段
RRF 融合后排序不对 代码里 rank 没 +1 检查 1/(rrfK + rank + 1)
两路结果差异大 某路召回太少 调大 bm25_top_k / vector_top_k
