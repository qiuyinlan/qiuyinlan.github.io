LeetCode 141. 环形链表：快慢指针为什么必相遇

题目

LeetCode 141. 环形链表（简单）

https://leetcode.cn/problems/linked-list-cycle/

给你一个链表的头节点 head，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 next 指针再次到达，则链表中存在环。为了表示给定链表中的环，评测系统内部使用整数 pos 来表示链表尾连接到链表中的位置（索引从 0 开始）。注意：pos 不作为参数进行传递，仅仅是为了标识链表的实际情况。

如果链表中存在环，则返回 true，否则返回 false。

进阶：你能用 O(1)（即常量）内存解决此问题吗？

一句话结论

快指针每次走 2 步，慢指针每次走 1 步。有环则必相遇。

它直接来自那条进阶要求 —— 只允许 O(1) 空间，就不能用 map 记录「哪些节点走过」（那要 O(n)）。空间卡死，思路只能往「两个指针互相追」上走。

为什么一定追得上

进环之后，两个指针都在环里跑，速度差恒为 1 —— 快指针每轮比慢指针多前进 1 格。

把环看成一圈跑道，慢指针在前面，快指针在后面追，每轮拉近 1 格。

环长 L 是有限的，所以最多 L 轮，两者的距离一定会被拉近到 0。

关键点：速度差是 1，所以不会跳过。 如果快指针一次走 3 步、慢指针走 1 步，速度差变成 2，而环长是偶数时就会一直在两侧交替，永远踩不到同一格。

逐行要点

slow := head / fast := head
:= 是声明新变量并自动推断类型。两个指针都从同一条起跑线出发，复制的是地址，不是节点。

for fast != nil && fast.Next != nil
Go 的 for 不写圆括号。&& 是短路求值：左边为 false 时右边不求值。

顺序不能反。 因为循环体里要执行 fast.Next.Next，如果先判 fast.Next != nil，当 fast 本身是 nil 时，取 fast.Next 就已经 panic 了。

slow = slow.Next / fast = fast.Next.Next
= 是赋值，改已经存在的变量。这里不能写 :=，否则编译报 no new variables on left side of :=。

if slow == fast
比较的是指针值，即「是不是同一个节点」。不是比较 Val，两个节点数值相同但地址不同，一样是 false。

字段名是 Next，大写 N。Go 用大小写控制可见性，写在结构体里的字段叫 Next，写 next 直接编译报错。

手跑一遍

输入 [3,2,0,-4]，pos = 1，也就是尾节点 -4 的 Next 指回节点 2。

轮次 slow fast
起点 3 3
1 2 0
2 0 -4
3 -4 -4

第 3 轮踩到同一格，返回 true。

LeetCode 142. 环形链表 II（中等）

https://leetcode.cn/problems/linked-list-cycle-ii/

给定一个链表的头节点 head，返回链表开始入环的第一个节点。如果链表无环，则返回 null。

如果链表中有某个节点，可以通过连续跟踪 next 指针再次到达，则链表中存在环。

不允许修改链表。评测系统内部使用整数 pos 来表示链表尾连接到链表中的位置（索引从 0 开始）。如果 pos 是 -1，则在该链表中没有环。注意：pos 不作为参数进行传递，仅仅是为了标识链表的实际情况。

提示

  • 链表中节点的数目范围在 [0, 10^4] 内
  • -10^5 <= Node.val <= 10^5
  • pos 的值为 -1 或者一个有效索引

进阶：你是否可以使用 O(1) 空间解决此题？

做法

相遇之后，把一个指针放回 head，两个人都改成每次走 1 步，再相遇的地方就是环的入口。

证明

设：

  • 头到环入口的距离 a
  • 入口到相遇点的距离 b
  • 环长 L

相遇时，慢指针走了 a + b，快指针走了 a + b + kL（k 是快指针多绕的圈数）。

因为快指针速度是慢指针的两倍：

kL - b 的含义是：从相遇点继续往前走，走到入口的距离。

所以「从头走 a 步」和「从相遇点走 kL - b 步」会落在同一个点 —— 都是环入口。

边界

  • 空链表 / 单节点：fast != nil && fast.Next != nil 直接为 false，返回 false，不 panic
  • 自环（head.Next = head）：第一轮就相遇
  • 无环链表：走到 nil 退出循环，返回 false

可能会被追问

「慢指针能不能走 3 步？」
能跑，但不好证明。速度差为 1 是唯一能保证「一定踩中、不会套圈跳过」的稳妥选择，面试直接答这句。

「为什么不用 map？」
O(n) 空间，题目进阶要求卡死了。而且 map 还要哈希，常数更大。
